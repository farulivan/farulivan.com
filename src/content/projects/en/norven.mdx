## The studio is fictional. The build isn't.

Norven is an architecture studio that doesn't exist. I imagined it for this
portfolio, because the point was never the firm. It was having a real site,
with real content and real constraints, that I could hold to production
standards without a client's deadline deciding what got cut first.

## What gets enforced

One command, `pnpm verify`, runs format, lint, typecheck, unit tests, build and
a bundle budget. On top of that, every pull request runs:

- **Playwright end-to-end tests with axe**, gating on WCAG AA. Not a report
  somebody reads later, but a gate that fails the PR.
- **Lighthouse CI budgets, per page.** Performance, accessibility, SEO and best
  practices each have a floor.
- **CodeQL and dependency review.**

What's interesting about putting the accessibility check in the gate rather
than the backlog is that it changes what you build. You can't ship the
component and fix the contrast later, so you pick the accessible version first
and never pay the difference.

## All motion through one runtime

The site is photography-led with scroll-driven motion. GSAP and ScrollTrigger
are underneath, but no component reaches for the library itself. Every effect
goes through one runtime, as a single `scrollEffect` callback that returns its
own cleanup.

One place to reason about what runs on scroll, one place to respect reduced
motion, and a pure core that unit tests without a browser.

## Deployment without credentials

Static output to S3, behind a single Cloudflare edge, with an IP-allowlisted
origin. Deploys run from GitHub Actions over OIDC, so there are no long-lived
AWS keys anywhere. Not in the repo, not in the CI settings, nowhere to leak.

The response headers (CSP, HSTS and Permissions-Policy) are committed as
Cloudflare Transform Rules rather than set by hand in a dashboard nobody can
diff.

A $5/month AWS budget sits over it as a ceiling. Steady state is about two
cents.

## Written down

The decisions live in the repo as ADRs, alongside a deployment runbook with the
cost analysis and a roadmap with explicit non-goals. If you're skimming it to
work out how I build, five minutes should be enough.
