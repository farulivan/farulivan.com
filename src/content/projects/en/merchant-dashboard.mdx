## The problem

Every merchant question ended in the same place: someone on the support team
opening a database client, writing a query, and pasting the result into an
email. The dashboard existed, but it answered questions nobody was asking — it
showed totals when merchants wanted to know which day went wrong.

## What I built

I started by reading six months of support tickets and grouping them by the
question underneath, which turned out to be four questions rather than the
forty different phrasings they arrived as. The console was rebuilt around those
four, with everything else reachable but not in the way.

The reporting layer moved to precomputed daily rollups, so a query that used to
scan the whole ledger reads a single row. Exports run on the same rollups,
which is why the numbers in a spreadsheet now match the numbers on screen —
they did not before, and that had been quietly costing trust.

Tests run against a seeded database rather than mocks, because the bugs that
mattered were all in the joins.
