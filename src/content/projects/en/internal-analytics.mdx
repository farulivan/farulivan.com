## The problem

Three teams tracked the same events under three names, so every cross-team
question started with an argument about whose export was right.

## What I built

A single schema for events, enforced at the point they are sent rather than
cleaned up afterwards, and a thin query layer over it. The interface is
deliberately small: a handful of saved questions and a way to change the date
range.

The important decision was refusing to build a general query builder. A tool
that can answer anything gets used to answer nothing, and the four questions
that actually drove planning were worth building properly.
